# 变更：M2 按请求采样并提交结果（已实现，待 GPU 验证）

## 1. 目标

消除旧采样路径的批次级假设：尚未完成的预填充（prefill，计算提示词的一段或全部 token）请求只应提交本轮 KV Cache（注意力键和值缓存）与计算进度，不应生成 token 或消耗随机数。

本次只建立逐请求的采样资格和结果提交语义；不实现真正的 prefill/decode 混合前向执行或混合调度。

## 2. 范围

- `nanovllm/engine/model_runner.py`
  - `ModelRunner.prepare_sample()`：从计划项读取可采样请求的 temperature。
  - `ModelRunner.run()`：在 sampler（采样器）调用边界按请求筛选、采样并回填结果。
- `nanovllm/engine/scheduler.py`
  - `Scheduler.postprocess()`：按单个计划项提交进度与生成 token。

未修改 `Scheduler.schedule()`、KV 块分配、模型输入元数据、attention（注意力）实现、CUDA Graph 或张量并行通信。

## 3. 修改前

```text
SchedulerOutput（纯 prefill 或纯 decode）
    ↓
ModelRunner.run()
    ↓
整批 logits + 整批 temperature
    ↓
Sampler 为每个请求生成 token
    ↓
Scheduler.postprocess() 按批次级 is_prefill 决定是否追加 token
```

部分 prefill 虽然会在 `postprocess()` 中被跳过，但已经进入 `Sampler`。这会推进 GPU 随机数生成器状态；同一请求的提示词分块方式因而可能改变后续真正生成时使用的随机数。批次级 `is_prefill` 也无法表达未来 mixed batch（混合批次）中每个请求各自的提交动作。

## 4. 修改后

```text
SchedulerOutput.scheduled（保持原计划顺序）
    ↓
ModelRunner.run()
    ↓
按计划项临时计算 sample_indices
    ↓
仅对可采样 logits 调用 Sampler
    ↓
list[int | None] 按原计划下标回填
    ↓
Scheduler.postprocess() 按 token 或 None 逐项提交
```

decode 请求始终可采样。prefill 请求仅当 `num_cached_tokens + num_scheduled_tokens == num_tokens`，即本轮完成提示词时可采样。未完成的 prefill 在结果表中对应 `None`；调度器先提交其 KV/计算进度，再停止该请求的后处理。

## 5. 关键差异

1. 采样资格在 `ModelRunner` 的实际采样边界临时计算，不写入 `Sequence` 或 `SchedulerOutput`。
   - 这避免为 M2 新增持久状态，并使随机数只由真实需要生成 token 的请求消耗。

2. `token_ids` 从“每项都是整数”变为“与计划等长的 `int | None` 列表”。
   - `sample_indices` 选出的 logits 和 temperature 被紧凑采样；采样结果再按原下标回填，保障结果始终对应原计划项。

3. `Scheduler.postprocess()` 不再读取批次级 `output.is_prefill`。
   - `None` 只对合法的未完成 prefill 有效；decode 或已完成 prefill 缺少 token 会触发断言，避免静默丢失生成结果。

4. `ModelRunner.run()` 的类型标注允许非 rank 0 张量并行进程返回 `None`。
   - rank 0 返回提交给调度器的结果列表；其他 rank 参与模型前向但不持有采样结果。

## 6. 架构决策

采样资格不作为 `ScheduledSequence` 的字段保存，而是在 `ModelRunner` 即将调用 `Sampler` 时由现有进度与本轮阶段推导。调度器拥有“本轮阶段”的决策，`Sequence` 拥有长期进度；采样器消费者组合这两项即可得到资格，新增字段只会制造第二个状态来源。

`None` 作为结果对齐占位符，而不是返回单独的“已采样请求列表”。后处理必须遍历完整执行计划以提交所有请求的 KV 进度；原顺序对齐的结果表能使每项提交保持局部、确定且无需重新匹配请求。

## 7. 不变量

1. 部分 prefill 必须推进 `num_cached_tokens`，但不得追加 token 或调用 `Sampler`。
2. decode 与完成提示词的 prefill 必须各自获得且仅获得一个对齐的采样 token。
3. `token_ids` 的长度必须等于执行计划项数；`None` 仅允许对应提交后仍未完成提示词的 prefill。
4. M2 仍拒绝同一 `SchedulerOutput` 中混合 prefill 与 decode；真正的联合前向执行属于 M4。
5. 纯 prefill 与纯 decode 的既有模型输入与执行路径保持不变。

## 8. 发现与后续工作

- 用户明确取消本地编译与单元测试；本次未保留测试文件，也没有任何本地验证结果可报告。
- 尚未验证：GPU 上的选择性采样、随机数状态不受部分 prefill 影响、张量并行 rank 间结果对齐，以及纯 prefill/纯 decode 回归。
- 后续 GPU 测试应至少比较“完整提示词”与“分块提示词”在受控随机种子下的生成结果，并覆盖一个部分 prefill、一个完成 prefill 和纯 decode。
- M3/M4 需要分别构造统一 mixed 元数据与一次真实联合前向；在此之前，`ModelRunner` 的 mixed-plan 拒绝检查必须保留。
